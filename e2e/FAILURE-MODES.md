# E2E failure modes

Each failure mode (F-id) lists the code location it targets and the spec(s) that exercise it.
Specs are in `e2e/specs/`. Run them with `npm run test:e2e`; the report is written to
`e2e/artifacts/report.md` and `e2e/artifacts/report.json`.

Specs marked "expected to fail" reproduce a known bug on the current code. A failing spec
for an F-id is the evidence that the bug exists; it should turn green once the bug is fixed.

## Background mode

On macOS, local runs ask the app to stay out of the way: the runner sets
`ROSI_LTS_E2E_BACKGROUND=1` in the Electron environment, and the app then uses an
accessory activation policy. The splash is never shown. The main window is shown
inactive, fully transparent (opacity 0), click-through, and not focusable, so it never
covers other apps. Background throttling is turned off. The runner
records the decision as `backgroundMode` and `backgroundReason` in `report.json` and
`report.md`.

Rules, applied in this order:

1. An explicit `ROSI_LTS_E2E_BACKGROUND` set by the caller ("1" or "0") always wins.
2. Only macOS (`darwin`) gets background mode. Other platforms get `0`.
3. `ROSI_LTS_E2E_FOREGROUND=1` opts out and sets `0`.
4. CI must not get background mode. `CI` set to any value other than empty,
   `false` or `0` counts as CI, so the mode is off. `CI=""` means not CI, and
   `CI=false` or `CI=0` also mean not CI.
5. Otherwise background mode is on.

Notes:

- Packaged builds ignore the flag. It only affects unpackaged runs.
- Native dialogs (`dialog.showErrorBox`, `dialog.showMessageBox`) still appear and
  cannot be hidden from the app. This is documented behavior, not a bug.
- Specs must not depend on window focus. Interaction goes through Playwright, which
  does not need the window to be frontmost.
- Each spec pre-seeds `"notifications": false` in its settings.json, so download-complete
  notification banners do not pop up. No spec currently needs notifications.
